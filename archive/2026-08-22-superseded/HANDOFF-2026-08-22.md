## 1 · 架构（实际形态）

两条**互不相通**的执行路径。这是本项目最容易被误解的一点：

```
路径 A —— 研究战役（竞赛证据的本体）
  campaign/run.sh (宿主)
    └─ docker compose run  →  container/entrypoint.sh
         └─ pi -p --autonomous --goal "…"
              --autonomous-gate ×4   (integrity/prereg/reconcile/review，/gates 只读挂载)
              --no-skills --skill ×5 (register/probe/grill/figure/loop)
              └─ IPython kernel（register 等四个 Python skill 装进 kernel venv）
    └─ 容器退出后：宿主**重跑**四道 gate → ledger.json（which-bound-ended）→ tar+sha256

路径 B —— Proma 桌面/浏览器产品
  apps/electron  →  pi-agent-adapter.ts  →  createAgentSession(...)
    工具只有 bash + edit（Proma 自己包权限）；ipython 注册但不激活
```

**路径 B 从不驱动战役。** Track B（会话驻留/refine/autonomous 透传）全部落在路径 B，
因此对竞赛证据零贡献。这不是缺陷，是设计选择——但下一个会话必须知道，
否则会去"修 Proma 让战役更好"，那是白做。

## 4 · 已知失败与不确定

### 4.1 从未验证的（不是"应该没问题"，是**没测过**）

| 项 | 为什么重要 | 怎么验 |
|---|---|---|
| kernel 跨 compaction 存活 | 计划的核心假设之一；长战役必然压缩 | 灌大上下文强制压缩，压缩后 `print(R)` 看 claim 数 |
| host continuations 越过 30 轮 | Step 0 判据二 | 需要一个真的要跑很久的 case |
| 并发/多实例写 register | `_reload_if_stale` 只窄化了窗口没关上；无锁 | 两个实例同时 abduce |
| `recompute kind: python` 在容器内 | 宿主已禁；容器内路径没测过 | 一个用 numpy 的 recompute spec |

### 4.2 与计划不一致 / 实现有问题

1. **长程无轨迹**：print 模式只在结束时输出。实测 container.log 分别 234 B / 942 B / 113 B。
   一次 90 分钟上百轮的战役事后只剩收尾发言。Prime 的逐轮 JSONL 写在容器内
   `/tmp/prime-home/.prime/agent/session-artifacts/`，**容器一退就没了**。
   修法（零代码）：把它挂到 `$ART/session/`。这也正是 P13–P17 证据链要的原材料。
2. **eval 按命令字符串冻结，不按内容**：改 `eval.py` 再提交，所有哈希照旧匹配。
   `:ro` 挂载挡住了容器内改写，但"内容冻结"仍未实现。
3. **会话驻留在默认运行时里空转**：默认走 utility adapter，每条消息 fork 一个进程并
   `process.exit(0)`。auto-refine 跨消息累计的收益**没有发生**。需要
   `PROMA_AGENT_RUNTIME=in-process` 才成立。
4. **refine 徽章读的文件 Prime 从不写**：Proma 调 local scope，而 `refinements.jsonl`
   只在 global scope 下写。徽章会永远显示"尚无经验记录"——比没有徽章更糟，
   因为它会被读成"提炼没在触发"的证据。
5. **autonomous IPC 是无人使用的任意命令通道**：renderer 传什么存什么，无校验，
   `gates` 最终以 `shell: true` 在宿主执行。渲染层与 research 皆**零调用者**。
6. **CONTESTED 没有证据下限**，完全凭模型自觉写不写 `contest` 分支。
7. **红→绿阳性对照只在单元测试里**，artifacts 里没有一次真实的 red→green 事件——
   而这是计划自定的"头号交付物"。
8. **`loop/references/` 约 40% 不可执行**：ChatGPT ×30、browser ×31、Playwright ×14 处
   指令，容器里只有 ipython 和一个 DashScope 出口。而 `SKILL.md:49` **明确路由**
   模型去读其中两个。这是 impossible-instructions 那一类。

### 4.3 这个 bug 类会反复出现，请专门防它

**impossible-instructions**：要求一个动作，但执行者够不到它的前提。本轮三个实例：

- review 要求每个 claim 有 verdict 行，reconcile 又拒绝无 artifact 的 H# → 报告无解
- 每个小数要 `(P#)`，而带 `(P#)` 的数字要对上重算值 → 给频段标出处必死
- `claim_view` 不含 graveyard，却要求子代理的 conflicts 点名 graveyard → grill 必败

**通用探测器**：一个断言"**所有** gate 对同一份诚实产物同时通过"的集成测试。
原先 10 个 gate 测试每个只跑一道、各自全绿，把三个矛盾全藏住了。

## 6 · 不可协商的约束

**人拥有**：密钥、花费、公开部署、force-push、`git push`（未经要求不做）。

**红线**：

- LLM 生成的代码**绝不**在宿主执行。宿主 gate 已禁 `kind:python`——**不要放回来**。
- `.env` / `dash.md` 是活密钥：不得 `cat`/`tail`，输出必须打码。
- `:4003` 必须留在 `127.0.0.1`（无鉴权 + docker.sock = 宿主 root）。
- web bridge 只绑 `127.0.0.1`，**永不** `0.0.0.0`。
- 不得修改或重启 `/home/lingxufeng/proxy/litellm/config.yaml`；`:4001` 是别的项目的共享网关。
- 不得暴露 `:4004` 与 web-bridge 到回环之外。
- 不得 fork Open WebUI；不得动 upstream `vendor/`；不得改 NeuronBench 评测代码。
- 不得让任何模型判断写 `accepted`。
- `~/ClawUI` 没有 git remote，**不要删**（112 个提交只存在于磁盘，tag `archive/specs-v1`）。

**当前两条红线未落实**（评审发现，需决策）：容器是普通 bridge 网络（**完全公网出口**，
计划写的 ":4004 网关 only" 从未实现），且 `DASHSCOPE_API_KEY` 在容器环境变量里，
模型一行 `os.environ` 就能读。叠加 = 一行代码把生产密钥发出去。
修法是同一件事：litellm :4004 放到专用 docker 网络，容器只连它、拿每轮可撤销的 token。

## 7 · 验证规则（每次改动后跑什么）

```bash
cd research && .venv/bin/python -m pytest -q gates skills viewer   # 期望 57 passed
```

（注意：**必须用 `.venv/bin/python`**，裸 `python3` 会 `ModuleNotFoundError: register`。）

产品侧：`bun run typecheck`（0 错误）、`bun test`（423/424，那 1 个失败是存量的
headless-Electron spawn 测试）、`bun run electron:build`。

改了 `research/skills/` 之后**必须**重建镜像，否则容器里跑的还是旧代码：

```bash
bash research/container/build.sh && docker compose -f research/container/compose.yaml build
```

改了 `~/oss/prime-agent` 之后：重建它的 dist **并**重跑 `bun install`
（bun 会 COPY `file:` 依赖，不是链接）。

**一次战役的机械验收**：

```bash
research/step0/check.sh research/artifacts/<RUN>      # 四项判据
python3 research/viewer/viewer.py research/artifacts/<RUN> -o run.html
```

**判断真假实现的通用手法**（本轮抓出多个"看着在跑其实没跑"）：

1. 找那条**运行时事件**：journal 行、session JSONL、IPC 事件、进程、文件哈希。找不到就是没跑。
2. 反向验证：**故意破坏它**，看有没有东西变红。不会变红的检查等于不存在。
3. 对"读文件判断状态"的代码，先确认**那个文件真的会被写**
   （refine 徽章就是栽在这——它读的文件 Prime 在 local scope 下从不写）。
4. 空输入测试：在空 register / 空产物上跑，如果全绿，说明检查都是对空集合的循环。
