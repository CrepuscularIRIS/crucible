## 重建时要带走的东西

**代码删掉，约束保留。** 下面五条是在真实运行里被验证过的，
重建时它们会变成 skill 的写法与 MCP 的接口，不要重新推导一遍：

1. **互斥频段**——预测频段两两重叠的实验是装饰性的：无论结果如何都落在某个分支里，
   信念状态不会改变。至少要有一对互斥频段，且至少一个分支 kill/scope 某个假设。
2. **先登记后执行**——预登记必须在执行**之前**落盘，带时间戳与哈希。
   事后补登记与"我本来就是这么想的"无法区分。
3. **从原始文件重算**——永不采信报告里的数字。指标必须按预登记锁定的规约
   从产物重算，并与报告中引用的数字对账。
4. **终态必须可追溯**——任何终态结论都要能追到一次真实落地的 probe，
   且日志里有对应记录。否则信念可以凭空改变而无人察觉。
5. **攻击者必须看得到 graveyard**——要求子代理"点名已死假设"，就必须把
   graveyard 给它看。不给却要求，它每次都必败。

## 最贵的三个教训

1. **四道 gate 曾对一场完全捏造的战役全绿**——实验从未执行、状态文件手改、
   报告数字编造。原因：所有 gate 都把模型写的状态文件当事实读，
   没有任何一道拿只追加的日志去对账。**gate 之间必须有一道检查"状态是怎么来的"。**
2. **impossible-instructions（本轮命中四次）**——要求一个动作，
   但执行者够不到它的前提。看着像模型不听话，其实是规则集自相矛盾。
   通用探测器：**一个断言"所有 gate 对同一份诚实产物同时通过"的集成测试**。
   旧的 10 个 gate 测试每个只跑一道、各自全绿，把三处矛盾全藏住了。
3. **"实现了但不可达"比"没实现"更危险**——它会被读成"功能没生效"的证据。
   判别四条：找不到运行时事件 → 没跑；破坏它没反应 → 检查不存在；
   读文件判状态的先确认那文件真的会被写；空输入全绿 → 检查都是对空集合的循环。
