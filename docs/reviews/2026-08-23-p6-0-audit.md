## 一、先说做对了的（已验证，别返工）

**1.2 的机制是对的。** 对着 Prime 源码逐条核过：
`_createRlmSubagentRuntimeOptions`（`agent-session.ts:9009`）确实按引用拷
`customTools`，但子代理是全新的 `new AgentSession`（:9083），
`_buildRuntime`（:8678）为每个会话重建自己的 `_baseToolDefinitions`。
所以把 `ipython` 从 customTools 里拿掉、改用 `initialActiveToolNames` 激活内置定义，
**确实**让每个会话（含子代理）拿到自己的 kernel。共享命名空间、
`RLM_MAX_DEPTH` 绕过、子代理产物落进父目录——三条随之关闭。

计量接口的核心设计也是对的：`simulate` 跑的是**agent 自提的候选机制**
（结构上不可能泄露真值）；`info` 用 `world.problem()`，benchmark 自己文档为
leak-free——实测 `reference_model` 是 plain 基线 `{extra: [], slow_na: false}`，
`text_prior` 刻意含糊（"an additional membrane current of unknown identity…"）；
`nb.load_world` 的 `stochastic` 默认 True，观测确实带噪。
`replay()` 对新 op 无 case 也无 default，静默跳过，**不破坏** trace/tamper。
meter 缺 python3/脚本时 `proc.status !== 0` 抛错，**fail closed**。
denylist 对不存在路径先 `existsSync` 过滤——这条很关键，bwrap 遇到不存在的路径会
整体失败、静默掉所有探针。

## 二、BLOCKING findings

### B1 · `forecast` 是可反复查询的评分神谕〔最严重〕

`forecast` **只有 CLI，没有 MCP 工具**（`server.ts` 只注册了 `world_observe`
与 `world_simulate`），而"终局只有一次"是**按 ledger 判**的
（`world-meter.py:161-163` 查 `entries` 里有没有 forecast）。换个 ledger 就是新的一次，
且 `cost=0` 不扣预算。实测：

```
guess=8  → spike_forecast_mse 61.46   budget_spent 0
guess=16 → spike_forecast_mse 66.13   budget_spent 0
guess=24 → spike_forecast_mse 198.80  budget_spent 0
```

MSE 是连续可爬的信号——agent 不花一次观测就能把 held-out 真值二分出来。
这是 ARFT C.2（grader-fitting）直接送到手上，**headline 指标随之失去意义**。

### B2 · `PROMA_RESEARCH_DENY` 在任何活路径上都没被设置

全仓 grep：该变量只出现在文档、注释、以及**自己给自己设值的那个测试**里。
campaign 脚本的 MCP `env:` 块、bootstrap，一处都没注入。
所以 1.3 的 denylist 是**实现了、测试了、但从不生效**——正是本仓库
栽过两次的"过了所有闸门却从不触发"。

### B3 · denylist 只包住 probe_run，kernel/bash 直通真值

`denyEntries()` 只在 `runSandboxedEval`（`sandbox.ts:117-143`）里用，
只有 `probe_run`（`server.ts:303`）走它。agent 自己的 kernel 是宿主 Python，
不过 bwrap。实测一行到手：

```python
>>> import neuronbench as nb; nb.WORLDS['h_sag']['desc']
'hyperpolarisation-activated inward Ih -> voltage sag and post-inhibitory rebound'
>>> nb.WORLDS['h_sag']['alt']
{'extra': [Chan(name='Ih', g=5.0, E=-30.0, mvh=-95.0, ...)], 'slow_na': False}
```

**P5.1 泄漏走的正是 kernel（ipython 的 `%%bash`），不是 probe_run。**
所以"真值在探针内不可达"属实，但它不是泄漏发生的那条渠道。

### B4 · 预算对 agent 没有约束力

`world-ledger.jsonl` 在 run 目录里、**没有 tamper 基线**（journal 有 sha256 基线）。
实测：

```
observe #1 (budget 1) → ok, cost 1
observe #2            → refused: "budget exhausted"
rm world-ledger.jsonl
observe #3            → ok, cost 1      ← 预算原地满血
```

另外三条同效旁路：换 `--ledger` 路径直接跑 CLI；`research_init` 一个新 run
拿全新 ledger（`first-campaign.ts` 未钉 `PROMA_RESEARCH_RUN`）；
`sys.path.insert` 后直接 `nb.load_world(...).run(...)`——不进 ledger 也不进 journal。

### B5 · `dispose()` 会中止 refine，8 秒排空救不了

Prime 自己的注释把话说死了（`agent-session.ts:3785-3787`）：

> Drain before marking `_disposing` so a refine triggered at the final
> agent_end completes **instead of being aborted by `dispose()`**.

而 `dispose()`（:3976-3994）明确 `_autoRefineReviewAbort?.abort()` +
`_refineAbortController?.abort()` + 清 timer。refine 是一次模型调用，
8 秒后大概率仍在飞——睡完再调那个会中止它的 API，等于没修。
**Prime 早就备好了正确入口 `disposeAsync()`。**

现状分布：`two-round-campaign.ts:238-239` 与 `routing-acceptance.ts:180-181`
是"睡 8 秒 + `dispose()`"；`first-campaign.ts:190` **连睡都没有**；
`p0-evidence.ts:218`、`rlm-runtime-e2e.ts:95` 同步 dispose。

## 四、修复计划（按依赖排序；每条自带验收）

**P6.0b-1 · 封死评分神谕**〔B1〕
把 forecast 收成 MCP 工具 `world_forecast`：run 内**一次**（判据取 journal 的
`world.forecast` 事件，不取 ledger），并让 kernel 无法直接 spawn meter CLI
（见 -3）。
✓ 验收：同一 run 第二次 `world_forecast` 被拒；换 ledger 路径的 CLI 调用在
评测接线下不可达。

**P6.0b-2 · 预算改由 journal 计**〔B4〕
`spent` 从 journal 的 `world.observe` 事件累加（它已经带 `cost`），
不再信任可写的 side ledger；ledger 降级为人看的明细。所有评测脚本钉
`PROMA_RESEARCH_RUN`。
✓ 验收：删掉 `world-ledger.jsonl` 后预算**不**回满；`research_init` 新 run 被钉死拒绝。

**P6.0b-3 · 真值对 agent 不可达 + 泄漏可测**〔B2 B3〕
① 评测 MCP spawn 注入 `PROMA_RESEARCH_DENY=<neuronbench 树>`；
② 注册 `world_*` 工具时若该变量未设 → **fail closed**（拒绝注册并说明），
杜绝"实现了但没接"；
③ neuronbench 树移出 agent 工作区；
④ 承认 kernel 不可沙箱化：`liveness.py` 增加"kernel/bash 读取或 import
benchmark 树"的检出，把泄漏**当成一个要报告的数**，不再宣称结构性封死。
✓ 验收：未设 DENY 时 `world_*` 注册失败；探针内读真值为空；liveness 能在
一场故意泄漏的 run 上报出来。

**P6.0b-4 · refine 真的能落**〔B5〕
五脚本一律 `await session.disposeAsync()`，删掉 8 秒魔法数。
✓ 验收：`p0-evidence.ts`（turnInterval=2）仍绿；campaign 跑完
`harness_state.json` 有新条目。

**P6.0b-5 · 归档与隔离护栏**〔M2 M4〕
① 五脚本统一归档 `session-artifacts`（`existsSync` 护栏，先归档后 rmSync）；
