# 认知维度上的拆解：赛题两条要求 → 两个轴 → 谁来做

## 两条要求，其实是两个方向的力

赛题 §2.1 的四项能力与 §2.3 的十字段，从认知上只有两个轴：

```
广度召回 Recall     领域里已经有什么          答案已经躺在语料里
精度对齐 Precision  这话到底对应什么可测的     答案还不存在，得逼出来
```

| 赛题要的 | 落在哪个轴 | 我们的机器 |
| --- | --- | --- |
| §2.1-① 文献挖掘与事实提取 | **召回** | `search_evidence` / `record_source` / `web-answer` |
| §2.1-② 逻辑驱动的假设生成 | **对齐** | `grill` 的重建 → `record_hypothesis` |
| §2.1-③ 论证可行与多轮迭代 | **对齐** | 结案规则 + `run_falsifier` |
| §2.1-④ 智能体思辨与人在回路 | 两者之间 | 多角色 + `ask_user` |
| §2.3 ⑩ 参考论文（严禁虚构） | **召回** | evidence 表只收真检索到的 |
| §2.3 ⑨ 实验结果 | **对齐** | 只从 `run` 表推导 |

**只做一半交不了。** 判伪循环再漂亮，没有证据就没有「科学事实表述准确性」那 15 分，
也交不出参考论文；只做召回则是一堆文献综述，没有可验证的假设。

## 选哪个轴：一条判据

> **下一个问题取决于上一个答案 → 拷问。
> 问题已经固定、答案在语料里 → 检索。
> 问题固定但答案有争议 → 多路独立判断再看分歧。**

这条判据比"先检索后推理"的流水线更准：科研里两者是**交替**的，
不是前后的。每拷问出一个新问题，就产生一次新的召回需求；
每召回一批新事实，就有新的东西需要被拷问。

## 为什么一问一答必须拆成两个角色

一个脑袋同时问和答，它会**挑自己答得上的问题问**。这是自证，不是拷问。

| 角色 | 谁 | 硬约束 | 为什么 |
| --- | --- | --- | --- |
| 追问 | 子代理 `grill` | **零工具** | 没有工具就无法自答，只能出问题 |
| 回答 | 子代理 `web-answer` | **只能联网搜**，不许读本地 | 本地是我们自己写的，拿它回答等于自证 |
| 决策 | 主智能体 | 全部工具 | 派谁、往哪走、什么时候收，只有它决定 |

实测（2026-08-15，界面真跑）：拿「磁场自由能越高，24 小时内出 M 级耀斑概率越大」
去跑一轮 ——
`grill` 156 秒，零检索，拆出五片独立可检验的片段，并指名
**「自由能↑⇒概率↑ 这个单调函数几乎没被当作函数直接检验过」是整句最可疑的焊缝**；
`web-answer` 525 秒，发了 8 条英文检索式去查这一条。
两边都没越界：追问的没给答案，回答的没读本地。

## 那条不许越的界

> **推理只能把一个说法降级。杀死它只能靠测量。**

拷问、辩论、审稿再犀利，也只能把 claim 降级或改写；判死只能由
`run_falsifier` 打印的 JSON 决定。守不住这条，一个能言善辩的追问者
就变成「快速消灭好工作」的机器 —— 这与 SPEC §8-2（LLM-as-judge
不能当科学正确性证明）是同一条。

## 自动模式长什么样

人扔来一个方向之后，**不再停下来问下一步做什么**：

```
方向 →[召回] 领域已有 →[拷问] 逼出承重且没验过的那块
     →登记可证伪假设 →[判伪] 真跑 →裁决落库
     →回到[拷问]：结果本身也是新说法
```

两条轨并行：**判伪实验发出去之后主智能体就自由了** ——
这时去拷问下一个候选、补证据、核引用，都不占它的资源。闲等着是失职。

具体怎么做已经沉淀在技能 `grill-loop` 里；这份文档只解释**为什么这么切**。
