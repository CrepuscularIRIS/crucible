## 2. 赛题核心任务（官方 PDF 口径）

围绕"**可验证科学研究假设的自动生成**"，聚焦以下核心任务：

> 参赛团队需围绕特定学科领域，基于超级智能体（如 OpenClaw、Hermes）或编程设计多智能体系统（Multi-Agent Systems）架构，利用国产开源大模型——**千问（Qwen）系列**，开发一个具备**问题理解、知识整合、关联发现与可验证假设生成**能力的 AI 系统原型，实现从"数据/文献输入"到"可验证科学假设输出"的智能闭环。

### 2.1 四项核心能力项（"科研灵感流水线"）

1. **文献挖掘与事实提取**：结合选题的结构化信息，提取关键科学事实，避免断章取义。
2. **逻辑驱动的假设生成**：利用归纳与演绎推理，基于已知事实生成初步假设。
3. **论证可行与多轮迭代**：挖掘跨学科技术迁移潜力，确保引用真实可靠、假设具备可行路径，并进行多轮迭代以完善提案。
4. **智能体思辨与人在回路**：构建可交互、具备教学意义的人机协作流程，对假设进行进一步辩论与迭代。

### 2.2 科研问题集参考（选题范围）

- **自然科学方向**：构建适配具体自然科学领域的 AI Scientist，链接该领域多维度、多模态实测数据（观测数据、实验数据、临床数据等）与文献知识、历史数据库资源；针对核心科学问题（异常现象识别、极端事件预测、内在机制挖掘、性能突破、路径优化、靶点发现等场景），通过智能体实现数据智能清洗、分析与关联挖掘，自动生成具备科学性、可验证性的科学假设、内在驱动机制解释或工程优化策略。
- **人文社科方向**：构建适配某人文社科领域的 AI Scientist，链接行为数据、交易数据等与相关规则（法规、监管政策等），针对核心需求（违规行为识别、风险预警、机制挖掘、假设生成、合规建议等场景），自动生成具备合理性、可验证性、合规性的行为假设、证据推理链、风险预警或合规操作建议。

### 2.3 生成结果规范：《科学假设与研究计划》标准字段

系统最终生成物必须包含以下标准化字段：

1. **待研究问题（Problem Statement）**：明确指出当前领域存在的具体局限性
2. **解决思路（Rationale）**：基于逻辑推理的创新点阐述，展示推导链条
3. **必要的技术手段（Technical Details）**：验证假设所需的具体技术栈（统计与机器学习、深度学习方法等）
4. **数据集（Datasets）**：来源合规真实的数据集
   - **Source**：假设推演依据的历史数据
   - **Target**：验证实验所需的拟采集数据特征
5. **标题（Paper Title）**：符合学术出版规范
6. **摘要（Paper Abstract）**：包含背景、方法、预期结果的完整摘要
7. **方法论（Methods）**：具体实施步骤，包括模型架构或实验流程
8. **实验设计（Experiments）**：包含基线对比（Baselines）及评估指标（Metrics）
9. **实验结果（Results）**：通过公式推导或实际执行，在一定范围内验证实验可行性
10. **参考论文（References）**：真实文献列表，**严禁虚构**

## 3. 选题方向（直播/官网口径）

### 3.1 官网最新版：三个方向 + 子题

答疑环节官方明确：**以官网最新版本为准**（团中央发布的最早期版本作废）。最新版三个方向为：① 科学问题；② 科学数据（场景）；③ 科学传播与艺术表现。详细要求见"阿里云高校合作"公众号近期推文（每个赛道有单独详细解释：整体题目要求、作品提交详细要求、可参考资料文献）。

#### 方向 1：科学实验任务规划与反馈迭代（官网原文，直播中放大抄录）

面向"从科学问题到可验证研究方案"的场景，搭建能够理解科学问题、整合文献与数据证据、生成候选假设、并进一步形成研究计划或实验任务闭环的 AI 应用。**重点不是给出泛泛的研究建议，而是展示 AI 如何提出可检查、可验证、可迭代的科学假设或实验方案**，并在接入虚拟仿真或实验仪器后，展示系统如何根据反馈结果继续迭代优化。两个子题：

- **A. 科学假设生成与研究计划设计**：面向《Science》125 个前沿科学问题，完成"问题理解—知识整合—候选假设生成—证据梳理—研究计划输出—反馈修正"。应用应说明假设从何而来、依据哪些事实/文献/数据、可能如何验证，并通过多轮资料补充、证据完善、方案评分、版本比较或人工反馈，展示自迭代提升过程。
- **B. 科学实验任务规划与反馈迭代**：面向虚拟仿真或实验仪器执行的闭环科研场景，完成"任务规划与实验设计—实验运行与数据获取—数据分析与反馈迭代"。**重点不是生成一次性实验方案，而是展示 AI 如何根据实验结果调整下一轮计划**。
- **注**：可自行选择科学问题、数据来源、模拟环境或实验仪器。**初赛评价关注**：闭环链条是否完整、计划是否可执行、假设生成是否有证据支撑、数据获取与分析是否真实影响下一轮计划、迭代优化过程是否清楚、每轮成效质量是否逐步提升。

#### 方向 2：金乌·太阳物理建模迭代与假设生成（官网原文）

围绕太阳物理中的数据分析、模型预测或科学假设生成任务，搭建能完成数据预处理、特征构建、模型预测、结果评估、自我校正或证据推理的 AI 应用。两个子题：

- **A. 太阳物理数据建模闭环**（待研究问题任选其一）：
  1. 基于活动区磁场数据，提取可量化其复杂度的参数，建立参数与耀发强度或频次之间的定量关系；并基于 **JW-SSD 数据集**构建太阳黑子的表征及分类方法；
  2. 基于多模态时序数据，探索数据特征与耀发活动之间的时序关联，并基于 **JW-FD 数据集**完成太阳耀斑爆发的精细化预测（1–72 小时，C/M/X 标签）；
  3. 基于公开 **TESS 光变曲线**，自动识别恒星耀发，并统计其形态、能量和频率分布。
- **B. 太阳物理假设生成与证据推理**（待研究问题任选其一）：
  1. 耀斑触发前兆因果链发现（磁能积累与释放、触发机制与先兆特征）；
  2. 日冕加热之谜（阿尔芬波加热、磁重联纳耀斑等主流理论对比，结合多波段观测与数值模拟寻找甄别证据）；
  3. 太阳活动周起源探秘（约 11 年周期演化规律、太阳发电机理论）。

### 3.2 直播中讲解的七大方向（李瑀旸，辅助理解选题）

按"起点"分类：一个科学问题 / 一批科学资料 / 一个科学内容 / 一个天文流程，对应七个方向：

1. **科学问题**（假设→实验计划→反馈迭代）：前沿问题假设、催化剂自动实验、仿真与仪器闭环、天文观测反馈。关键金句："关键不是一次性建议，而是证据、执行和反馈能连成闭环。"
2. **太阳物理**（太阳数据→预测模型→风险输出）：JW-FD 耀斑预报、JW-SSD 黑子分类、耀斑触发前兆因果链、日冕加热与活动周。"数据任务看输入、标签和错例；科学问题看假设、证据和验证。"
3. **数据场景**（数据整合→清洗对齐→分析输出）：天文数据整合（Ia 型超新星光变曲线多源 CSV）、地学材料数据整合、预测与学术影响分析、数据质量修正闭环。
4. **知识图谱**（实体关系→证据链→查询回答）：示例为系外行星观测证据图谱（TOI-1231 b / TESS / HARPS / JWST）；工具链 LightRAG → KAG → GraphRAG → Zep。"知识图谱不是概念图，而是能查询、能追溯、能修正的证据网络。"
5. **数字分身**（用户画像→个性服务→持续优化）：记住什么（身份、偏好、表达、边界）、何时更新、何时召回、如何交付（可运行应用、对话样例、画像版本）。"分身的核心，不是替你发言，而是稳定理解你。"
6. **科学传播**（内容创作→视觉表达→受众反馈）：中文文本人味化改写（诊断问题→改写文本→复核事实）；图文协同生成（标题、主图、注释、解释、证据五要素）。
7. **星语实训**（工具技能→任务运行→记录复盘）：把天文工具 AI Ready 化（skills 化 / MCP 封装），做成面向科普、科教、科研的能力包。"不是泛用天文聊天助手，而是可运行、可检查、可复用的能力组件。"

### 3.3 答疑中的方向归属澄清

- 方向一 A = Science 125 问题假设生成；方向一 B = 自选领域实验闭环任务，**无领域限制**（生化环材、计算机、交叉学科均可）。A/B 分开，选 B 不用做 125 题。
- 方向二**限定太阳物理**；恒星方向、太阳与其他学科交叉放到**方向一**做。
- 对天文感兴趣/零起步同学，讲者推荐用**太阳数据**起步（数据干净、研究积累多）。

- 125 题方向：评委看"对想法是否是潜在可验证问题"的思考，**讨论越详尽、越完备，得分越好**（答疑 Q9）。
- 结果是否可被验证、对该领域的人是否有启发性、对人类知识积累有无增量——"我们不只是关注技术方向"（李瑀旸）。

## 12. 直播中的方法论要求（评委视角，务必吃透）

### 12.1 核心方法论：闭环 + 可验证 + 人在回路

- **AI Scientist 的本质** = 科研闭环（提出问题→查找资料→设计验证→生成结果→人类把关→迭代）中的环节由 AI 驱动；与 ReAct 智能体框架同构。
- **"先让一个小闭环跑起来，比一开始追求大系统更重要。"**
- **"生成的假设已经变得廉价，只有被验证或可被验证的假设才有价值。"**——所有方向都必须有"结果验证→修改"闭环。
- **FDE（Forward Deployment Engineer）思维**：Vibe Coding 只是中间手段；评委想看到、且应写进技术报告的是——**之前**的需求调研、价值分析、痛点挖掘，**之后**的结果评估、反馈迭代。"技术是手段，Science 需求是目的，不做空中楼阁的技术。"
- 人机关系定位：**人是导师，agent 是学生/助手**；把系统科学思维（找矛盾→主要矛盾→拆解问题→确定对象→调研现状→提出新问题→研究设想）教给 AI 执行。
- 迭代反馈来自 AI 可以，**来自人并被利用起来更好、值得鼓励**（人在回路/圆桌讨论式迭代）。
- 最终让 AI 把科研过程沉淀为可复用的 **skill + 接口**——"这就是 AI Scientist"。

### 12.2 选题建议

- **选方向不是选难度，而是选你最容易跑通的第一条闭环。**
- 根据自己的特长或兴趣选**一个**方向做深，**不要试图全都做出来**——时间有限，不要抱太高期望。
- 从真实需求出发：先自己跑一遍、自己先做出来，再领域普世化。
- 开源框架只是参考，**不要局限自己的技术想法**；必须保持独立性——"跟着别人做很难取得好结果"。
- 已有人做的方向（如学科数据提取）说明有需求，但**要想清楚差异化**。
- 中文场景注意**文字幻觉**问题（中文幻觉概率明显高于英文，各厂商模型普遍存在）。

### 12.3 各方向技术要点与验收导向（陈昭宇 + 幻灯片）

| 方向 | 核心要求 | 交付导向 |
|---|---|---|
| 科学问题/机制推理 | 资料检索→假设生成→证据归纳→反例复核→假设更新；人要兜底（判断证据可信度、检查因果跳跃、确认可实验验证） | 候选假设清单、支持证据表、反例与冲突点、下一步验证计划 |
| 实验任务闭环 | 订计划→记执行→改下一轮；执行结果必须影响下一轮目标设定 | 计划表、执行日志、结果报告、下一轮建议 |
| 预测类任务 | 可视化→预处理→建模→评估→错误归因→再训练；"不是只交一个分数" | 分类/风险预测、指标与置信度、误判样本清单、修正日志 |
| 数据整合 | 先找全（多源检索召回）、再抓准（结构化抽取）、最后合得上（标准化对齐）；缺口回查闭环 | 来源清单、抽取表格、冲突说明、整合数据（CSV/JSON/KG）、证据文件、抽取报告 |
| 知识图谱 | 能回答"是什么"，更要能证明"为什么、从哪里来"；**可追溯性是第一要务**；没有证据闭环就不是真正的图谱方案 | 实体关系图、查询与证据回答（含可靠性评分）、修正闭环 |
| 学术影响力预测 | 优先遵守学术伦理；只用标题摘要误差大，要加作者/机构/引用网络；因子与拟合方式**必须可解释**；**留验证数据集**定位偏差；先把影响力指标定义清楚再选路线 | 预测结果（多维+置信区间）、解释报告、偏差分析、复核记录 |
| 文本人味化改写 | 不是单 prompt 去 AI 味；诊断→锁定（术语/数据/引用不可改）→改写→复核→反馈；事实与术语保护优先于语言华丽 | 改写版本、修改理由、事实核验、风格记录、diff 与回滚版本 |
| PPT→教学视频 | 核心难点不是视频生成，而是课件理解、讲解结构、字幕时序和质量检查；六环节：PPT 解析→讲稿→TTS/数字人→字幕对齐→合成→质检回改 | 可讲、可听、可审查的课程视频；数字人是高阶方向（算力/模型/系统要求更高） |
| 科研图像生成 | 科学语义正确、结构可编辑、审查可追溯；四大审查维度：图文一致、元素完整、概念准确（不虚构机制/变量/关系）、文字可控（无伪文字错字乱码、小字不可读✗） | 可编辑导出（源文件/矢量图）、审查报告与版本记录 |
| 数字分身 | 画像多维、辅助而非代替人；使用中"无感"评估与更新 | 可运行应用、对话样例、画像版本 |
| 科普 AIGC | 除艺术表达外核心是**科学性**：选可靠参考资料 + 对事实的结果控制；**期望沉淀可复用的生产工作流**（成为工具而非单件作品） | 作品 + 生产工作流（图片、视频等形式） |

### 12.4 RAG/检索技术建议（答疑 Q2，官方推荐栈）

- 标准流程：文档 → embedding 向量化 → 向量数据库 → 相似度召回 → re-ranker 精排 → 输出。
- 推荐三件套：**百炼平台 Qwen embedding 系列**（多模态 embedding 刚更新）+ **Qwen re-ranker 系列** + 高效向量库（嘉宾提到一个阿里开源向量库，转写音近"ZVIC"，具体名称待群内确认）。
- 进阶：**Agentic RAG**（关键词拆分、语义理解、结果加工都用智能体节点扩充），典型参考 **Deep Research**；百炼已上线 **Deep Research 32B 开源模型**。
- **规模告诫**：几十/几百/上千篇算小规模；几万、几十万篇时准确性快速下降——**必须前置过滤（如 GraphRAG），控制单次匹配总量**。
