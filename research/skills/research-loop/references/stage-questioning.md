# 阶段问题债——每一步都要问到能改变动作的问题

**何时加载：** 进入或准备退出 ABDUCE / PROBE / GRILL / REPORT 阶段时；发现自己
只是“想过了”却说不出由此改变了什么时。

问题的单位不是深刻程度，而是**决策分叉**：至少有两个可信答案，并且答案会
导向不同动作。只有一个可信答案是在确认；答案不同但动作相同是在装饰。

推理、反问和审查可以 DEMOTE、SCOPE、REFRAME；只有落地测量可以终结 claim。
这条边界防止流利的质疑者仅靠语言淘汰好方向。

## 六类问题

| 类型 | 要问什么 | 必须排出的产物 |
|---|---|---|
| S1 隐藏前提 | 这件事要成立，什么必须先为真但还没写？ | 新假设，或明确 `no change, because` |
| S2 自我矛盾 | 它是否违背现有 claim、scope、控制标准或旧裁决？ | finding、attack，或无变化理由 |
| S3 可计算定义 | 两个人能否从同一输入独立算出同一量？ | 计算规约、重写后的 statement/metric |
| S4 假设阶梯 | 不替 claim 辩护；它依赖什么？上游前提是否更便宜可测？ | 重定向后的 falsifier/prereg |
| S5 失败边界 | 最小的反例、输入或设置是什么？ | 能失败的控制臂与频段 |
| S6 来源 | 这是测得、推导、引用还是假定？ | 证据定位，或仍为 LIVE 的显式标记 |

## 分阶段装配

- **ABDUCE：S1 + S3。** 先暴露前提，再保证 statement/predicts 是可计算对象。
- **PROBE/SELECT：S2 + S4。** 花成本前，检查现有承诺并优先测试更便宜的上游前提。
- **PROBE/prereg：S3 + S5 + S6。** 把定义、失败边界和证据来源冻结进 question、
  bands、branches 与 metricSpec。
- **GRILL：S1 + S2 + S5。** 对手找遗漏前提、内部冲突和最小击穿条件。
- **REPORT：S2 + S6。** claim 状态变化后重做一致性与来源审计。

不是固定问卷：顺序和措辞由当前 finding 决定，但该阶段列出的类型必须全部清账。

## 清账与停止

每类问题出现以下任一产物即清账：

1. 父会话通过 Research MCP 写入 claim、prereg、transition 或 attack；
2. 写入 `RULINGS.md` 的 scope/reframe 裁决，并点名后续动作；
3. 一行明确的 `no change, because <可核验理由>`。

“值得以后想想”、没有动作的风险列表和 child 报告本身都不算清账。阶段退出前
复核一次；未清问题留在本阶段，不把债滚到最终报告。

## S2 五种高收益扫描

从锚和 `research_state` 自上而下检查：

1. 一个机制依赖了未登记的前提；
2. 一个宽泛 claim 建在被 scope 的前提上；
3. 一个结论依赖仍未检验的支持；
4. claim 仍为 LIVE，但它的 falsifier 已经落地；
5. 两个 claim 或两条裁决不能同时为真。

发现只产生 finding，不自动改状态；父会话按证据处理。
