# forks —— `forks: wait` 时的研究分叉（F-a）

**何时加载：** K0 确认了 `forks: wait`，且一次 `claim_transition` 被宿主拦下、
拒绝文本以"研究分叉 F-a"开头（只凭少量测量否定一条假设）。
`forks: auto`（默认）时宿主不拦：同一判定只在画布上打标，你照常写 RULING 继续。

*why：这类迁移（reps 少、一组参数、无仿真来源的频段）是本系统最常见的误杀点；
用户在 K0 选了 wait，就是要在这里亲自决定。持久化、默认阻塞、永不静默批准，与 K0 同。*

## 程序

1. **不重试**被拦的那次迁移，也不绕道别的工具达成同一结论。
2. **单独调用 AskUserQuestion**：同一批工具调用里只有它一个——不与任何别的工具
   （ipython、MCP、读文件）放在同一批。
3. 问题的 header 以"研究分叉 F-a"开头；正文一句话说清：哪个 H#、凭哪个 P#、几次测量。
4. ≤3 个选项，都是研究选择；每个 description 固定三段：`解决：… ｜ 成本：… ｜ 仍不确定：…`。
   被规则挡住的选项照列，在 description 末尾写 `blocked_by: <规则>`。
5. 等回答。默认阻塞，你不替用户选。
6. 回答到达（消息带 `[U#]`）→ 先在 RULINGS.md 写一行 `U#: <决定> · affects <H#/P#>`，
   再按回答迁移、收窄或改设计。

## 选项示例（格式示范，与任何具体 world 无关）
