# MOVE: triage —— 落带外分诊（强制移动）

**LOAD WHEN（事件触发，强制）：** 探针落地在**所有**预登记频段之外 ·
`claim_transition` 被 server 拒（观测不在任何 branch 频段内）· 观测与锚中任一
LIVE 假设的 predicts 冲突。

**何时不用：** 带内结果（预登记规则机械适用，无需分诊）；FAILED 探针
（崩溃不是意外，是没有观测——修命令重登即可）；想给一个你不喜欢的频段
翻案（频段已冻结，分诊只处理带外事实，不重审预登记）。

这是移动库的点火器：reframe / derive / abduce 的多数触发都在"承认残差是真的"
之后才会发生。带外观测是现实在说话——但多数意外是垃圾，台阶从便宜到贵。

## 诊断台阶（在三分法内部按序爬，不许跳）

1. **指标伪影**——重算路径（json 路径/正则）取错了东西？换一种聚合/连续指标
   还在吗？
2. **实现 bug**——evalCommand 或被测代码错了？对数据/评测路径做一个针对性检查。
3. **方差**——换种子/换切分还复现吗？残差在噪声带内吗？
4. **已知现象**——文献里已有解释吗？（本系统无外部检索：判"已知"只能靠参数记忆，
   必须写明线索出处并降格处理，不许当新发现。）
5. **真实意外**——以上全部排除，才是新现象。

## 出口——每个都是 journal 落账，没有"写下来就算处理过"

| 判定 | 出口（必须执行，不是建议） |
|---|---|
| **伪影 / bug**（台阶 1–2） | 修好命令或代码后 `prereg_write` 一个**新探针**（改命令 = 新探针），question 里写明旧探针 P# 的失效原因。旧探针不适用 branches，不做终态依据。 |
| **方差**（台阶 3） | 频段宽度写错了：按 `derive.md` 重推一个宽度诚实的频段，`prereg_write` 新探针。这次带外会显示在报告的校准段（`research_kit.calibration`）——照实写。 |
| **已知**（台阶 4） | 落成 `attack_record`（kind=constraint："残差由已知现象 X 产生，设计未控制它"，附出处线索）→ 下一个 prereg 带对应控制臂；若它使 claim 在本战役不可判 → 收窄声明素材送 research-report。 |
| **真实意外**（台阶 5） | **强制 `claim_propose`**：statement 主张一个产生该残差的机制，predicts 引用观测值（"观测 X=v 落在全部 LIVE 频段外；本假设主张机制 M 产生它，另预测 Y"），conflicts 点名它冲击的假设。 |

**绝不事后解释着把结果塞进旧频段。** 分诊必须以上述落地之一终结；在此之前
不开新的探针方向——带外指标做不了任何终态依据（server 会持续拒绝迁移），
拖着不分诊只会让锚的落地未迁移计数一路涨。

## 为什么强制

- ARFT F.4（82.5%）：agent 找到问题、写下来、然后照旧交付——诊断产生了文本
  而没有产生状态变化。三个出口都是状态变化，堵死"写下来就算处理过"。
- 赛事模板 P11：重新生成方案 ≠ 反馈迭代。**分诊出口产生的 propose/prereg
  就是"第二轮由第一轮的具体测量结果引起"的因果连接件**，journal 里可逐字追溯。

## 禁止

- 不跳台阶（"肯定是真发现"最常死在台阶 1–3，各花几分钟）。
- 不在分诊未终结时 `report_declare`。
- 不把台阶 4 的"已知"当垃圾桶——判已知必须给出处线索，给不出就回台阶 5。
