# 高判别力实验语法——先定位瓶颈，再做完整实验

**何时加载：** claim 涉及“X 是瓶颈/承载信息/导致收益”、多组件或多模态归因、
控制组难设计、或候选实验只能回答“有没有提升”而不能回答“为什么”。

先做最小诊断 probe，目的是把昂贵实验压缩成一个已定位的判别问题。诊断 probe
也必须 prereg；“便宜”不等于可以先看结果。

## 选择原则

1. 先写竞争机制和它们预测的**差值/排序/曲线形状**。
2. 找到一个只改变 load-bearing variable、其它轴尽量相同的 intervention。
3. 同时设计最强的 mundane alternative 控制；不能击穿 claim 的 control 是装饰。
4. 先跑能砍掉整条方向的上界/下界，再跑解释细节的完整实验。
5. 每个读数都写解释边界：它授权哪类判断，又不能证明什么。

## 八种常用设计

### 1. Oracle rescue：测贡献上界/充分信息缺口

给系统注入正常运行时拿不到的理想信息或理想组件，比较：

- status quo；
- privileged/oracle；
- 同形状 matched-noise 或 shuffle。

大幅 rescue 表示该信息缺口有高贡献上界，并且下游至少能利用理想信息；小幅 rescue
意味着只改这一路的收益天花板很低。它**不证明**实际组件是唯一瓶颈，也不证明
具体机制。进一步定位可加：语义错误但格式正确的 wrong-answer 臂、跨样本 swap 臂、
完全移除该模态的 ablation 臂，以及按 bits/rank/resolution 降质的 dose 曲线。

**多模态例：** 把视觉/音频模态的正确答案直接作为受控输入给下游模型。若成绩大幅
提升而 shuffle/swap 不提升，说明缺失的语义信息具有高上界；接着比较“原始模态”、
“oracle 答案”、“同格式错误答案”、“移除模态”，才能区分感知提取、接口传递与
额外 token/格式效应。不要从 oracle 单臂直接写“融合模块是瓶颈”。

### 2. Amputation：测必要性

移除/置零/冻结组件 X，并用等秩、等能量或等计算量的随机移除作控制。性能下降只说明
当前系统依赖 X；若 oracle rescue 又很大，才形成“有用且当前未充分利用”的上下界。

### 3. Swap / permutation：区分语义、身份与形状

保持张量形状、长度和边际分布，打乱样本对应、标签对应、位置或通道。原信号有效而
swap 失效说明身份/对应关系重要；两者同样有效说明收益更可能来自形状、额外容量或
正则化。shuffle 必须在预登记里定义随机化单位，避免泄漏结构仍被保留。

### 4. Dose-response：让机制承诺曲线而非点

连续改变信息质量、遮挡比例、rank、噪声、上下文长度或干预强度，预测单调性、斜率、
拐点或 arm ordering。机制若只能解释一个点，通常是故事；曲线形状更难被事后调参
伪造。剂量轴必须可控，停止阈值必须预登记。

### 5. 2×2 因子/交叉干预：区分 root 与 shadow

分别干预候选根因 A 与可见影子 B，形成 A×B 四臂。若只改 B 能恢复表征指标却不恢复
行为，B 是修复杠杆但未必是根；若改 A 同时消除 B 和行为缺陷，A 更接近因果根。
交互项比两个独立 before/after 更能判断“二者是否只是同一效应的影子”。

### 6. Matched-pair diagnostic：隔离混杂

从同一 source 构造只在目标属性上不同的成对样本；或让 ambiguous 与 explicitly
resolved 版本共享其余表面形式。必要时把评分函数、prompt format、feature extractor
本身设为自变量：效应随“尺子”替换而消失，说明现象可能在测量工具而不在系统。

### 7. Sufficiency × necessity battery：避免只做 probe correlation

“可线性读出”不等于模型使用。先证明信息可读，再投影/删除目标方向观察行为，并对
等秩随机方向做同样操作；最后用只含目标变量的简化输入尝试恢复主要效应。读出、必要性、
充分性三者的组合比单一 probe 更接近机制证据。

### 8. Limit-then-surpass：先证极限，再建 remedy

先找出方法类不能区分/表达的最小反例或必要充分条件，再构造只补入缺失结构的增强对象。
同一个结构对象最好同时承担 impossibility witness 和 remedy；否则“发现限制”和“新模块”
可能只是两篇未连接的故事。比较时同时保留原方法的成本轴。

## 每个实验的控制矩阵

至少逐项核对：

| 轴 | 应保持一致或显式操纵 |
|---|---|
| 数据 | 同样本、切分、预处理、选择规则 |
| 模型 | 同 checkpoint、seed、解码设置 |
| 预算 | 同 token/样本/推理调用/训练步数 |
| 操作规模 | 同 rank、能量、维度、幅度 |
| 测量尺 | 同 metric 代码；若尺子是怀疑对象则作为显式因子 |
| 随机性 | ≥3 seeds 或诚实 scope；固定随机化单位 |

对照不能只“看起来公平”：不同臂的任何额外差异，都是你真正测到的 treatment。

当前 Research MCP 每个 probe 用一个标量 metric 做 bands/branches。多臂设计必须在
prereg 中先定义一个决策量，例如 `oracle - status_quo`、`oracle - wrong_answer`、
交互项或 dose slope，并让 metricSpec 重算它；其它臂读数可留在同一 stdout artifact
供审计，但若要单独移动 claim，必须各自有预登记的判别量，不能事后挑最漂亮的差值。

## 从诊断到完整实验

1. T0/T1：推导、源码检查、已有资产核验；
2. T2：合成微型实例或缓存表征上的诊断，先验证方向上限和控制有效性；
3. T3：冻结模型上的受控干预，得到 claim-changing 读数；
4. full：只有便宜层级存活后才做跨 seed/模型/数据的确认。

升级前回答：便宜 probe 排除了什么？完整实验还新增哪个约束？如果 full 只是把同一
读数做大，先停下来提高设计的判别力。

## 解读禁区

- rescue 大：高上界，不等于实际路径因果归因；
- ablation 降：当前依赖，不等于该组件是最优或唯一机制；
- probe 可读：存在信息，不等于模型使用信息；
- matched control 不动：排除该控制覆盖的替代解释，不等于排除所有混杂；
- 跨模型复现：增加 scope，不自动提供机制。

这些边界应直接进入 prereg 的 question/branches，避免结果落地后把“投资判断”升级成
“机制结论”。
