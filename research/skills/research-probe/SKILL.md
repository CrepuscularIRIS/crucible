# research-probe —— 判别性探针

## 你在做什么

设计一个能**改变信念**的实验。判别力是唯一标准：这个实验的结果落在哪里，
会杀死/收窄哪个假设？答不上来的实验不要做。

## 程序

1. `research_state`（或 kernel 里的锚）：找到你要判别的 LIVE 假设对（至少两条）。
2. **SELECT——先比再登**：写出 ≥2 个候选探针设计，各自填频段表后用
   `research_kit.disjoint_pairs(bands)` 数互斥对，选**互斥对多、成本低**的那个。
   只想出一个设计就登记，是把选择题偷换成了判断题。
3. 写预登记 `prereg_write`，四样缺一不可：
   - **question**：这个探针判别什么，**并点名对照**——什么对照能否证这个读数
     （"若 X 只是重新居中，打乱标签的对照臂应同样提升"）。没有对照臂的读数
     只是一个数字；
   - **evalCommand**：一条确定性的命令（输出指标到 stdout，json 或单行文本）；
   - **bands**：每条被检验假设的预测频段——**必须存在一对不重叠频段**，
     否则无论结果如何信念都不变，server 会判为装饰性探针并拒绝；
   - **branches**：每个频段对每条假设的处置（kill / scope / support），
     **必须有 kill 或 scope**——探针必须有能力否定。
4. `probe_run`：受认可执行路径只运行预登记时冻结的命令。非零退出记 FAILED，
   不予落地——这不是失败被惩罚，是保护：崩溃与干净结果不可区分，
   FAILED 探针永远不能成为终态依据。
5. 落地后按 branches 应用结果：`claim_transition` 把被杀/被收窄的假设送进
   graveyard。

## 落带外：分诊台阶，不是重写预登记

观测值不落在任何分支频段内时，transition 会拒绝。这是现实在说话，按台阶分诊，
**走完才许下结论**：

1. **指标伪影**——重算路径（json 路径/正则）取错了东西？
2. **bug**——evalCommand 或被测代码有实现错误？
3. **噪声**——换种子/换切分还复现吗？
4. **已知**——这是文献里已解释的现象吗？
5. **真实意外**——以上都排除，才是新现象：回 research-abduce 把它登记成
   新假设，配新探针。**绝不事后解释着把结果塞进旧频段。**

## 命令纪律（沙箱契约）

probe_run 在 bwrap 沙箱里执行你的命令，契约是**结构性**的，不是请求：

- 文件系统**只读**——中间文件只能写 `/tmp`，结果走 stdout（server 在沙箱外捕获）；
- **无网络**——命令不能依赖下载、API、远程数据；
- 环境变量只有 `PATH` / `HOME=/tmp` / `LANG`——拿不到宿主密钥，也别试图读；
- 超时（默认 10 分钟）按失败处理，不予落地。

因此 evalCommand 必须：可重放（无随机性或固定种子）、无网络、无时间依赖、
指标从 stdout 重算（json 点路径或正则捕获）——不要写需要跑代码才能得出的指标。
改命令 = 新探针。预登记后命令不可改（sha256 冻结）。

## 禁止

- 不为"收集数据"而跑探针——每个探针都要杀死点什么。
- 不在预登记里写 `[0, 1]` 这种全频段——那是把判别力偷换成了安全感。
- 不重复已落地的探针（同 question、同 bands）。
