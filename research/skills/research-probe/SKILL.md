# research-probe —— 判别性探针

## 你在做什么

设计一个能**改变信念**的实验。判别力是唯一标准：这个实验的结果落在哪里，
会杀死/收窄哪个假设？答不上来的实验不要做。

## 程序

1. `research_state`：找到你要判别的 LIVE 假设对（至少两条）。
2. 写预登记 `prereg_write`，四样缺一不可：
   - **question**：这个探针判别什么；
   - **evalCommand**：一条确定性的命令（输出指标到 stdout，json 或单行文本）；
   - **bands**：每条被检验假设的预测频段——**必须存在一对不重叠频段**，
     否则无论结果如何信念都不变，server 会判为装饰性探针并拒绝；
   - **branches**：每个频段对每条假设的处置（kill / scope / support），
     **必须有 kill 或 scope**——探针必须有能力否定。
3. `probe_run`：受认可执行路径只运行预登记时冻结的命令。非零退出不予落地，
   这不是失败，是保护——崩溃的运行和干净的结果不可区分。
4. 落地后按 branches 应用结果：`claim_transition` 把被杀/被收窄的假设送进
   graveyard。观测值不落在任何分支频段内时，transition 会拒绝——那是现实
   在告诉你预登记写错了，回到第 2 步用新的探针修正，不要事后解释。

## 命令纪律

- evalCommand 必须可重放：无随机性（或固定种子）、无网络依赖、无时间依赖。
- 指标重算只认 json 点路径或正则捕获——不要写需要跑代码才能得出的指标。
- 改命令 = 新探针。预登记后命令不可改（sha256 冻结）。

## 禁止

- 不为"收集数据"而跑探针——每个探针都要杀死点什么。
- 不在预登记里写 `[0, 1]` 这种全频段——那是把判别力偷换成了安全感。
- 不重复已落地的探针（同 question、同 bands）。
