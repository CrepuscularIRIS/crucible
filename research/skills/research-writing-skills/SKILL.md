# research-writing-skills —— 用 RED/GREEN 开发研究 skill

## 你在做什么

把 skill 文本当**可测试的代码**：先看着 agent 在没有 skill 时失败（RED），
针对它逐字的借口写 skill（GREEN），新借口出现就加对策（REFACTOR）。
Prime 的 `rlm()` 让这件事不需要手工开会话——子代理就是测试机。
开发期 skill：留在 crucible 仓库用，不随战役工作区安装（见 README）。

## 铁律

```
没看过 agent 在无 skill 时失败，就不知道 skill 教的对不对
```

**违反字面就是违反精神。** 凭想象写的借口表防的是想象中的 agent；
真 agent 的借口（P4.3："只看一眼格式对不对"）比想象的更体面、更难拦。

## 程序

1. **RED**：构造压力场景（见夹具格式），在**未安装目标 skill 的工作区**跑它
   （子代理继承父级 skills，`rlm()` 卸不掉——所以 RED 要么换工作区，要么
   接受弱化版：prompt 不点名 skill，但 `<available_skills>` 仍列着它，结果
   只算下界）。逐字记录失败行为与自我辩护。
   ✓ 成功条件：拿到至少一条可引用的原话借口。
2. **GREEN**：针对**那些具体借口**写/改 skill——每条实测借口进"借口 | 现实"
   表，现实栏引用实测后果（"P4.3 实测……"比"不应该……"有力十倍）。
   ✓ 成功条件：同场景带 skill 重跑，行为改变。
3. **REFACTOR**：带 skill 的子代理找到新绕法 → 新借口进表 → 重跑。
   ✓ 成功条件：连续两轮没有新借口。
4. **存夹具**：场景存成目标 skill 目录下的 `test-pressure-<名>.md`——
   它是回归资产：以后每次大改该 skill，重跑一遍夹具。
5. **版本递增**：每个被修改的 skill，frontmatter `version` 必须 +0.1。

## 文本形式规则（写 GREEN 时遵守）

| 失败类型 | 标准写法 |
|---|---|
| 懂规则但压力下跳过 | 铁律 +"违反字面就是违反精神" + 借口/现实表 + 红旗句 |
| 输出形状不对 | **正面模板**写清输出长什么样、什么顺序——禁令会被话术协商掉，正面模板不会 |
| 漏必要要素 | 模板里的 REQUIRED 槽位 |
| 行为依赖情境 | 条件规则钉在**可观察谓词**上（"锚里出现 ⚠"，不是"必要时"） |

另外四条：
- **description 只写触发**（"Use when …"），绝不概述工作流——概述会让模型
  以为不用读正文；
- **禁止模糊豁免**（"除非重要""一般情况下"）——豁免句重开谈判；
- **Match the Form**：结构能拒绝的（server/gate/schema）标【结构】，只有
  结构够不着的判断才用纪律文本，并说明为什么结构够不着；
- **仪式随任务伸缩，gate 不伸缩**（research-loop 的遭遇战/会战棘轮是范例）。

## 夹具格式（`test-pressure-<名>.md`）

```markdown
# test-pressure: <名>
target-skill: <skill 名> v<版本>
source-incident: <实测来源，如 P4.3 (2026-08-23)>

## 场景（给被测 agent 的输入，自包含）
## 无 skill 基线（RED，实测记录）
逐字借口: "…"
实际行为: …
## 有 skill 期望（GREEN）
## 观察点（对应借口表的哪一行）
```

## 借口 | 现实

| 借口 | 现实 |
|---|---|
| "这条纪律很明显，不用测基线" | ARFT 800 条轨迹：明显的纪律被照做然后无视。基线不是仪式，是唯一能证明 skill 有用的对照臂。 |
| "借口表我能想出来，不用跑 RED" | 想象的借口防想象的 agent。P4.3 真实借口是"只看一眼格式"——没人想象得出它这么合理。 |
| "改动很小，不用重跑夹具" | 小改动最常撕开旧封口。夹具三分钟，回归一整场战役。 |

## 交接

- 夹具的场景需要真实战役状态 → 用临时目录造 journal/register（参考
  `packages/research-mcp/src/research-kit.test.ts` 的合成夹具写法）
- 新借口来自真战役 → 同时更新 `docs/reviews/` 里对应战役的摩擦清单
